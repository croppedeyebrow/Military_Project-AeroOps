# 데이터베이스 아키텍처

## 저장 원칙

- 업무·공간·시계열 데이터를 PostgreSQL/PostGIS에 통합한다.
- 원본 텔레메트리는 불변 데이터로 보존한다.
- 최신 상태는 별도 테이블로 유지해 관제 조회 비용을 줄인다.
- 모든 시각은 UTC, 위치는 WGS84(SRID 4326), 고도는 m를 사용한다.
- 경계 컨텍스트별 테이블 소유권을 지정하고 다른 컨텍스트의 테이블에 직접 쓰지 않는다.
- Spring Data JPA Entity를 도메인 간 계약으로 공유하지 않는다.

## DDD 데이터 소유권

| 경계 컨텍스트 | 소유 테이블 예시 | 외부 제공 방식 |
|---|---|---|
| Mission Operations | `missions`, `mission_routes` | Application Query·Domain Event |
| Command & Control | `commands`, `command_events`, `control_leases` | C2 API·Outbox Event |
| Operational Picture | `telemetry_frames`, `asset_latest_state` | Snapshot Query·Observation Event |
| Safety & Policy | `geofences`, `failsafe_policies` | Versioned Policy Decision |
| Incident Management | `alerts`, `incidents` | Incident Query·Event |
| Identity & Audit | `users`, `roles`, `audit_logs` | 인증 Claim·Append-only Audit |

## 핵심 테이블

| 테이블 | 핵심 필드와 역할 |
|---|---|
| `assets` | 기체 식별자, 유형, 모델, 상태 |
| `missions` | 임무명, 상태, 시작·종료 시각 |
| `mission_routes` | 예정 경로 LineStringZ |
| `geofences` | 구역 유형과 Polygon |
| `telemetry_frames` | 위치·속도·자세·배터리·통신 원본 |
| `asset_latest_state` | 기체별 최신 정상 프레임 |
| `alerts` | 경보 유형, 심각도, 근거값, 확인 상태 |
| `users`, `roles` | 사용자와 권한 |
| `audit_logs` | 행위자·행동·대상·결과·시각 |
| `commands` | 요청자·대상·payload hash·만료·현재 상태 |
| `command_events` | 승인·전달·ACK·실행·취소·timeout 이력 |
| `device_certificates` | 인증서 fingerprint·유효기간·폐기 상태 |
| `sync_sessions` | 단절 전후 sequence·snapshot·조정 결과 |
| `deployments` | Git SHA·image digest·설정·스키마·규칙 버전 |
| `operation_sessions` | 운용 구간과 deployment_id 연결 |
| `event_log` | 재생 가능한 정규화 도메인 이벤트 |
| `control_leases` | 기체별 통제 주체·운용 세션·유효기간·인계 이력 |
| `mission_feasibility` | 경로·에너지·탑재체·입력 신선도와 판단 결과 |
| `incidents` | 상관된 경보·영향 임무·심각도·조치 상태 |
| `command_effect_checks` | 명령 기대 상태·관측 상태·검증 결과 |

## 주요 인덱스

- `telemetry_frames(asset_id, event_time desc)`
- `unique(asset_id, sequence_no)`
- 위치·경로·구역에 GiST 공간 인덱스
- 미확인 경보에 부분 인덱스
- `commands(target_asset_id, status, expires_at)`
- `command_events(command_id, occurred_at, event_no)`
- `event_log(operation_session_id, event_time, stream_sequence)`

## 보존 전략

MVP에서는 30일 보존을 가정한다. 원본 삭제 전 일별 요약과 시험 결과를 보존하며, 실제 삭제 정책은 환경변수로 제어한다. 파티셔닝은 데이터 증가가 확인된 뒤 일·월 단위로 적용한다.

## 정합성 검증

- 배터리 0~100, 위경도·각도 범위 CHECK
- mission과 asset의 참조 무결성
- 최신 상태의 timestamp가 후퇴하지 않는지 검증
- 이력 재생 프레임 수와 원본 조회 결과 비교
- 명령 상태 전이 CHECK 및 event_no 유일성
- 운용 세션의 deployment_id 필수 연결
- 인증서 fingerprint 유일성과 폐기 시각 검증
- 필드별 관측·수신 시각과 신선도 상태 검증
- 통제권 Lease의 기체별 활성 구간 중복 방지
- Command 완료와 효과 검증 결과를 별도 보존

## 이벤트·배포 추적성

모든 telemetry, command, alert, sync 이벤트에는 `operation_session_id`, `deployment_id`, `schema_version`, `correlation_id`를 연결한다. 배포 레코드는 변경하지 않고 새 버전으로 추가한다. 따라서 특정 장애 시점에 어떤 코드·컨테이너·규칙·데이터 계약이 사용됐는지 역추적할 수 있다.

## AI·MLOps 추가 테이블

| 테이블 | 핵심 필드 |
|---|---|
| `feature_windows` | asset_id, window_start, feature_schema_version, features |
| `anomaly_predictions` | model_version, score, label, fallback_used, evidence |
| `knowledge_documents` | document_id, classification, version, content_hash |
| `knowledge_chunks` | chunk_id, document_id, text, metadata, embedding |
| `ai_analysis_runs` | run_id, incident_id, model, prompt, knowledge_snapshot, result |
| `model_deployments` | model_name, version, alias, image_digest, approved_by |
| `dataset_snapshots` | dataset_id, schema_version, query, hash, scenario_ids |
| `evaluation_results` | target_version, dataset_id, metrics, gate_status |

Embedding Index는 `pgvector`, 키워드 검색은 PostgreSQL FTS를 사용한다. 운용 원본과 AI 생성 결과를 같은 테이블에 섞지 않으며, AI 결과는 삭제·재생성 가능하지만 원본 사건 Event는 불변으로 보존한다.

## 보안 데이터 규칙

- 인증서 Private Key와 CI Secret은 DB에 저장하지 않는다.
- Audit Event는 Append-only 권한을 적용한다.
- AI 계정에는 Knowledge·Event 읽기와 Analysis 쓰기만 허용한다.
- Command 상태 변경은 Control Service 계정만 가능하다.
- 민감 필드는 로그·LLM Context로 전달하기 전에 Redaction한다.
