# 3단계 — 수집·저장 파이프라인 (Day 5~7)

## 목표

Command와 Telemetry 채널을 분리하고, 텔레메트리의 검증·수집·저장 및 명령 이벤트의 신뢰성 있는 기록 기반을 만든다.

## 작업

- 수집 API와 Redis Streams producer 구현
- consumer group 기반 처리기 구현
- telemetry, latest_state, asset migration 작성
- 중복·역순 프레임 처리 정책 적용
- 최신 상태와 기간별 이력 API 구현
- 수신량·거부량·처리 지연 기본 메트릭 추가
- Redis stream·consumer group·서비스 계정을 채널별 분리
- command, command_event, event_log, deployment migration 작성
- transactional outbox와 idempotency key 기반 구현

## 완료 기준

- 10대 데이터를 손실 없이 저장한다.
- 중복 데이터가 이중 반영되지 않는다.
- 역순 데이터가 최신 상태를 후퇴시키지 않는다.
- 기간·기체 조건 이력 조회 테스트가 통과한다.
- Telemetry 계정으로 Command stream 쓰기가 거부된다.
- 같은 idempotency key의 명령이 하나만 생성된다.

## 산출물

수집 파이프라인, migration, API 문서, 정합성 시험 결과.
