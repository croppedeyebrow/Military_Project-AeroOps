# AeroOps V07 — Kotlin·방산 DDD 전환 실행 문서 세트

이 문서 세트는 가상 드론과 불안정한 통신 환경을 이용하여 Telemetry 수집, 안전한 Command 처리, 장애 재현, 로컬 LLM 기반 운용 지원, MLOps, DevSecOps를 통합 검증하기 위한 개발 기준서다.

## V05 개정 요약

- 핵심 백엔드를 Kotlin + Spring Boot 3 + Spring Modulith로 전환했다.
- 방산 무인체계 용어를 기준으로 Core/Supporting/Generic 하위 도메인과 경계 컨텍스트를 정의했다.
- React + TypeScript 관제 프론트엔드는 유지했다.
- Python은 AI·MLOps, C++은 시뮬레이션·Codec·Replay, Rust는 보안 통신·Edge Gateway에 배치했다.
- Go는 CI/CD 보조 도구, 배포 검증, 모니터링 Exporter와 운영 CLI에 배치했다.
- 제한망·내부 Registry·신뢰 구역·통제권·이중 승인·감사 추적을 방산형 배포 원칙에 반영했다.

## V06 개정 요약

- GitHub `croppedeyebrow/Military_Project-AeroOps`의 2026-10-19 `master` 구조를 기준선으로 분석했다.
- 이미 구현된 FastAPI 7단계 기능을 보존하면서 Kotlin C2 Core로 옮기는 단계적 전환 전략을 추가했다.
- Python 코드를 무조건 폐기하지 않고 AI·MLOps로 재배치하며, C++·Rust·Go 도입 순서와 완료 조건을 정의했다.
- 신규 구축용 20일 로드맵과 별도로 실제 레포 전환용 8단계 개발 Backlog를 추가했다.
- 각 기능의 현행 소스, 목표 경계 컨텍스트, 이관 방식, 병행 운용 및 제거 조건을 연결했다.

## V07 개정 요약

## 설계 원칙

1. LLM은 설명·검색·권고만 수행하며 기체 명령을 직접 실행하지 않는다.
2. Command와 Telemetry는 스키마, 채널, 권한, 보존 정책을 분리한다.
3. 원본 이벤트는 불변으로 보존하고 현재 상태는 별도 Projection으로 만든다.
4. ACK 손실을 명령 실패로 단정하지 않으며 중복 실행보다 불확실 상태를 우선한다.
5. 모델 장애 시 규칙 기반 판단으로 Fallback한다.
6. 코드, 이미지, 모델, 프롬프트, 데이터셋 버전을 운용 세션과 연결한다.
7. 실제 무기 운용·표적화·공격 자동화는 범위에서 제외한다.
8. 핵심 운용 규칙은 Kotlin 도메인 모델에 두고 외부 프로토콜·DB·AI와 분리한다.
9. Python은 AI·MLOps, C++·Rust는 시뮬레이션·통신, Go는 배포·관측 운영 도구에 사용한다.
