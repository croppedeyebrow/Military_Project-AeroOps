## 구현 내역

### 계약 기준선

- `tests/contracts/baseline/`: 현행 FastAPI의 REST(OpenAPI 30개 경로)·WebSocket 메시지·
  Redis Stream 계약을 파일로 고정. 생성은 `legacy-backend/scripts/export_contract_baseline.py`,
  변경 감지는 `legacy-backend/tests/test_contract_baseline.py`.

### Golden Replay

- `tests/contracts/replay/run_golden_replay.py`: 시뮬레이터 고정 seed 입력(11개 데이터
  시나리오 + 7개 명령 흐름)을 HTTP로 넣고 최종 Asset/Alert/Command/Audit 결과를
  `tests/contracts/golden/fastapi_replay.json`과 비교. 구현 언어와 무관하게 `--base-url`만
  바꿔 Kotlin에도 실행 가능.
- 기준선 점검 중 기본 `battery_drop`(25%p)이 경보 임계값에 닿지 않아 경보 판정이 기준선에
  안 잡히는 것을 발견 → 85%p `battery_low` 시나리오 추가.

### 설계 결정·문서

- ADR 0004: Strangler, 단일 쓰기 주체, Dual Write 금지, 검증 전 FastAPI 삭제 금지.
- ADR 0005: `boot_id` 도입. 현행 결함(재부팅 시 `sequence_no` 리셋으로 새 프레임이 중복 폐기됨)을
  해결하는 설계와 Expand/Contract 적용 시점.
- `docs/planning/13`: 용어 사전 21개, Context Map(모듈·테이블·API 대응), 이관표, 불변조건 8개의
  현행 보장 수준, REQ→TEST 추적표.

## 설계 결정 (Day 1 이후 확정, 2026-10-24)

- **스키마 소유는 Kotlin(Flyway)**: 제안(Alembic 유지)을 바꿔 승인. Alembic은 `0005`에서 동결하고
  Flyway Baseline이 이를 이어받는다. legacy가 쓰는 테이블은 Expand 전용으로만 변경한다.
- **`boot_id` 제약 교체 시점**: legacy의 `ON CONFLICT (asset_id, sequence_no)` 때문에 Telemetry 쓰기
  주체가 Kotlin으로 넘어가는 시점으로 늦춘다.
- **레포 구조**: FastAPI를 `legacy-backend/`로 이동(삭제 아님), `backend/`는 Kotlin 전용.

## 테스트/검증

- 완료 게이트("같은 시나리오 반복 시 비교 가능한 결과")를 충족: 같은 DB에서 Golden Replay를 두 번
  연속 실행해 결과가 바이트 단위로 일치.
- `legacy-backend`: `ruff` clean, `pytest` 65 passed / 74 skipped(서비스 필요 시험은 서비스 없이 스킵).

## 남은 이슈 / 다음 단계로 이월

- Golden에 없는 것: 지오펜스·RSSI 경보, 재동기화, 운용 세션 재생, PENDING_APPROVAL timeout,
  `boot_id` 재부팅 시나리오(ADR 0005 구현 시 추가).
- 불변조건 3번(ACK 누락 → `UNKNOWN`)과 4번(Dispatch 직전 권한·통제권·세션 재검증)은 현행이 목표에
  못 미친다 — Kotlin 4단계 전에 ADR로 결정.
- `event_log`를 4개 모듈이 직접 INSERT하는 경계 위반은 Kotlin 4단계에서 Port/Outbox로 해결.
