# AeroOps 14일 구조 전환 로드맵

## 목적

이 일정은 기존 FastAPI 7단계 구현을 버리고 새로 만드는 계획이 아니다. 기존 Contract와 Replay 결과를 기준선으로 고정한 뒤, Kotlin C2 Core를 중심으로 목표 구조의 핵심 경로를 수직적으로 완성하는 압축 일정이다.

| 단계 | 기간 | 목표 | 핵심 완료 게이트 |
|---|---:|---|---|
| 1 | Day 1 | 기준선·전환 계약 | Golden Replay·API/Event Snapshot 확보 |
| 2 | Day 2~3 | Kotlin·Spring Modulith 기반 | 모듈 경계·DB·보안·관측성 CI 통과 |
| 3 | Day 4~5 | Operational Picture | Freshness·UNKNOWN·멱등 Projection 비교 |
| 4 | Day 6~7 | Mission·C2 | 통제권·승인·상태 전이·Outbox 검증 |
| 5 | Day 8~9 | Rust 통신 경계 | mTLS·QoS·재접속·Backpressure 검증 |
| 6 | Day 10~11 | C++ Simulator | 결정적 Clock·Fault·Replay 결과 일치 |
| 7 | Day 12~13 | Python AI·MLOps·Go Ops | 근거 AI·Lineage·배포 검증·Fallback |
| 8 | Day 14 | 통합 Cutover | E2E·보안·성능·Rollback 증거 생성 |

## 일정 해석

14일 안에 모든 기존 Python 업무 코드를 제거하는 것은 목표가 아니다. Kotlin이 `Operational Picture → Mission → Command` 핵심 경로의 쓰기 주체가 될 수 있음을 검증하고, Rust·C++·Python·Go 서비스는 최소 동작 수직 절편으로 연결한다.

## 공통 완료 기준

- 모든 변경은 REQ-ID와 TEST-ID에 연결한다.
- 상태 전이와 Event 발행은 함께 검증한다.
- 정상 시험보다 손실·지연·중복·단절·재시작 시험을 우선한다.
- 코드, Schema, 정책, 모델과 배포 버전을 결과에 기록한다.
- 실패한 단계는 다음 단계 기능으로 덮지 않고 완료 게이트를 다시 통과한다.
