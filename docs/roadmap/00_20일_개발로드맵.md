# AeroOps 20일 개발 로드맵

| 단계 | 기간 | 목표 | 완료 게이트 |
|---|---:|---|---|
| 1 | Day 1~2 | 프로젝트 기반 | 전체 서비스 실행, CI 통과 |
| 2 | Day 3~4 | 계약·장애 시뮬레이터 | 손실·지연·역순·단절 재현 |
| 3 | Day 5~7 | 채널 분리·수집·저장 | Command/Telemetry 격리와 정합성 |
| 4 | Day 8~10 | 2D 관제·재동기화 | 10대 표시와 단절 복구 |
| 5 | Day 11~13 | 명령·승인·경보 | 승인·취소·ACK·timeout 동작 |
| 6 | Day 14~15 | 3D 상세 뷰어 | 선택 기체 자세 동기화 |
| 7 | Day 16~18 | 이벤트 재생·배포 추적 | 장애 재현과 버전 역추적 |
| 8 | Day 19~20 | mTLS·통합 검증·배포 | 기체 신원과 전체 회귀 검증 |

## 일정 원칙

- 매 단계 종료 시 실행 가능한 통합 상태를 유지한다.
- 다음 단계 기능보다 현재 단계 완료 게이트를 우선한다.
- Cesium, ML, 실제 기체 연결은 20일 범위 밖으로 둔다.
- 매일 README의 실행법과 결정 기록을 함께 갱신한다.

## 최종 필수 증거

1. Command와 Telemetry의 분리된 스트림·ACL
2. 명령 상태 전이와 승인·취소·timeout 기록
3. 손실·지연·역순·단절 시험 로그
4. 재연결 후 sequence·snapshot·미종결 명령 조정 결과
5. 유효·만료·폐기 인증서의 mTLS 시험
6. 동일 이벤트 재생을 통한 장애 재현
7. 운용 로그에서 Git SHA와 image digest 역조회
