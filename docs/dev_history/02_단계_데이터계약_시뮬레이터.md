### 시뮬레이터

- [`simulator/simulator/scenarios/base.py`](../../simulator/simulator/scenarios/base.py): `Pose`,
  좌표 변환 유틸(`offset_latlon`, `bearing_deg`, `horizontal_distance_m`, 각도 정규화).
- `scenarios/circle.py`, `scenarios/straight.py`, `scenarios/waypoint.py`: 원형·직선(왕복)·

  `TelemetryFrame` 시퀀스를 생성. 배터리는 시간에 따라 선형 소모, RSSI는 RNG 기반 지터.
- [`simulator/simulator/faults.py`](../../simulator/simulator/faults.py): 7종 장애 주입 함수
  (중복·지연·역순·결측·GPS 점프·통신단절·배터리급락) + `apply_faults` 디스패처.
- [`simulator/simulator/sinks.py`](../../simulator/simulator/sinks.py): 전송 목적지 추상화
  (`HttpSink`/`StdoutSink`/`ListSink`) — 3단계 이전에도 `--sink stdout`으로 독립 검증 가능.
- [`simulator/simulator/main.py`](../../simulator/simulator/main.py): Typer CLI(`run` 서브커맨드),
  seed·num-drones·frequency-hz·scenario·duration-sec·faults·sink·ingest-url·real-time 옵션.

## 설계 결정

- **계약 중복 구현**: backend/simulator가 각자 Docker 빌드 컨텍스트를 가지므로(모노레포지만
  컨테이너 경계 분리) 공유 패키지 대신 계약을 양쪽에 독립 구현하고 데이터 사전을 SSOT로 삼는다
  ([ADR 0002](../decisions/0002-telemetry-contract-duplication.md)).
- **heading vs yaw**: `heading_deg`(지면 진행 방향, [0,360))와 `yaw_deg`(기수 방향, [-180,180])를
  별개 필드로 유지. 무풍 시나리오에서는 두 값이 같지만 계약·화면 모두 구분해서 다룬다.
  기본 시나리오는 무풍을 가정하므로 실제로는 `yaw_deg = to_signed_deg(heading_deg)`.
  같은 이유로 `roll_deg`/`yaw_deg`/`pitch_deg`는 서로 다른 범위([-180,180] / [-180,180] / [-90,90])를
  갖는다.
- **장애 주입은 "전송 순서/누락/값 이상"만 표현, 계약 위반은 만들지 않음**: 계약 위반(범위
  이탈) 검증은 별도 테스트(`test_telemetry_schema.py`, `test_contracts.py`)로 다룬다.
- **전송 계층 분리(Sink)**: 로드맵 완료 기준이 "정상 프레임은 계약 검증을 통과한다"이지 "실제
  HTTP 전송이 성공한다"가 아니므로, 3단계에 생길 `/telemetry` 엔드포인트 없이도 시뮬레이터를
  독립적으로 끝까지 검증할 수 있게 sink를 추상화했다.
- **시뮬레이터 CLI를 `run` 서브커맨드로 유지**: Typer는 명령이 하나뿐이면 서브커맨드 이름 없이
  바로 호출되게 축약하는데, 기존 `simulator/Dockerfile`의
  `CMD ["python", "-m", "simulator.main", "run"]`과 README 예시가 `run`을 서브커맨드로
  기대하고 있어 `@app.callback()`을 추가해 그룹 모드를 강제했다.

## 테스트/검증

```
cd backend && pytest        # 16 passed (health 2 + telemetry_schema 14)
cd simulator && pytest      # 26 passed (contracts 7 + scenarios 6 + generator 4 + faults 9)
cd backend && ruff check .  # app/tests 대상 통과 (alembic/env.py의 기존 경고는 무관)
cd simulator && ruff check . # All checks passed
```

CLI 수동 검증:

```bash
python -m simulator.main run --num-drones 2 --duration-sec 3 --sink stdout --no-real-time
# → 정상 TelemetryFrame JSON 6건 stdout 출력 확인

python -m simulator.main run --sink http --ingest-url http://localhost:9999/telemetry \
  --no-real-time --faults duplicate,gps_jump,disconnect
# → 엔드포인트 없음(연결 거부)에도 예외 없이 경고 로그만 남기고 정상 종료 확인
```

완료 기준 대비:

- ✅ 정상 프레임은 계약 검증을 통과한다 — `test_valid_frame_passes` 외.
- ✅ 잘못된 위경도·배터리·각도는 거부된다 — `test_out_of_range_values_rejected`(양쪽 계약).
- ✅ 동일 seed 실행 결과가 일치한다 — `test_same_seed_produces_identical_output`.
- ✅ 최소 6개 장애 시나리오 테스트가 통과한다 — 7종 모두 개별 테스트(`test_faults.py`).

## 남은 이슈 / 다음 단계로 이월

- `HttpSink`가 실제 backend에 데이터를 성공적으로 적재하는지는 3단계(`POST /telemetry` 구현)
  이후에 end-to-end로 검증한다.
- 시뮬레이터 스캐폴드 `.env.example`은 `SIMULATOR_SINK`를 아직 포함하지 않음 — 필요 시 추가.
- 원형 시나리오의 뱅크각(15도 고정)은 시각적 구분용 근사치이며 물리 모델은 아님(문서화됨,
  `simulator/simulator/scenarios/circle.py` 주석 참고).
