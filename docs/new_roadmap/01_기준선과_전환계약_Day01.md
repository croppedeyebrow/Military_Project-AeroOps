# 1단계 — 기준선과 전환 계약 (Day 1)

## 목표

기존 FastAPI 결과를 새로운 Kotlin 구현이 비교할 수 있는 기준선으로 고정한다.

## 작업

- 기존 REST/OpenAPI, WebSocket Event, Redis Stream Schema Snapshot 저장
- 정상·손실·지연·역순·중복·단절·ACK 손실 Scenario 실행
- 최종 Asset State, Command State, Alert와 Audit 결과 저장
- `asset_id`, `boot_id`, `sequence_no`, `event_time`, `correlation_id` 계약 확정
- Ubiquitous Language와 Context Map 작성
- FastAPI→Kotlin 기능 이관표와 제거 금지 불변조건 확정
- ADR: Strangler, 단일 쓰기 주체, Dual Write 금지 기록

## 산출물

Contract Snapshot, Golden Replay Dataset, Context Map, ADR, 요구사항 추적표.

## 완료 게이트

같은 Scenario를 반복했을 때 허용된 시간 오차를 제외하고 비교 가능한 결과가 생성된다.
