# 2~8단계 작업 분해

1단계(프로젝트 기반)는 완료된 상태(모노레포, Compose, CI, health endpoint, ADR 0001)를 기준으로,
남은 2~8단계를 실제 파일·모듈 단위 작업으로 분해한다. 각 단계는 로드맵 문서(`0N_단계_*.md`)의
목표·완료 기준·산출물을 그대로 따르며, 여기서는 "무엇을 어디에 만드는가"를 구체화한다.

## 진행 원칙

- 각 단계 작업은 착수 전 사용자 승인을 받은 뒤 구현한다.
- 단계 완료 시 README의 "현재 상태" 배지와 `docs/decisions/`에 필요한 ADR을 갱신한다.
- 매 단계 종료 시 `docker compose up`으로 전체 서비스가 여전히 기동되는지 확인한다.
- 백엔드 모듈 경계(`backend/app/modules/{ingestion,telemetry,mission,alert,realtime,identity,audit}`)와
  프론트 컴포넌트 경계(`frontend/src/components/*`)는 이미 스캐폴드되어 있으므로 그 구조를 유지한다.

## 2단계 — 데이터 계약·시뮬레이터 (Day 3~4)

**선행**: 없음 (바로 착수 가능)

### 작업

- [ ] `backend/app/schemas/telemetry.py`: `TelemetryFrame`에 각도(roll/pitch/yaw) 범위, `flight_mode` enum,
      `sequence_no >= 0` 등 검증 규칙 보강. `event_time`/`received_at` 관계 validator 추가.
- [ ] 데이터 사전 문서 신설 (예: `docs/api/telemetry_frame_dictionary.md`): 필드별 단위·축·범위·좌표계(WGS84,
      m, UTC) 표로 정리. `docs/planning/05_데이터엔지니어링_아키텍처.md`의 정의를 구체화.
- [ ] JSON 예제 fixture 추가 (정상 프레임 1개 + 오류 유형별 1개씩), 위치는 `docs/api/` 또는
      `simulator/tests/fixtures/`.
- [ ] `simulator/simulator/contracts/`: `TelemetryFrame`과 동일한 계약을 시뮬레이터 쪽에 정의(백엔드와
      스키마 버전 동기화 방법을 ADR로 기록 — 공유 패키지 대신 버전 필드로 맞출지 결정).
- [ ] `simulator/simulator/scenarios/`: 원형·직선·경유지 3종 비행 경로 생성기 구현 (위치·heading 계산).
- [ ] `simulator/simulator/main.py`: 10대 × 1 Hz 정상 프레임 생성 루프 구현, `seed`로 재현 가능한 RNG 사용,
      `scenario_id` 부여.
- [ ] 오류 주입기 구현 (최소 6종, 아래 중 선택): 중복, 지연, 역순, GPS 점프, 통신 단절, 결측, 급격한
      배터리 하락.
- [ ] 전송 계층: HTTP client(예: `httpx`)로 `POST /telemetry` 전송 코드는 작성하되, 실제 엔드포인트는
      3단계에 생기므로 로컬 실행 시에는 stdout/파일 sink로도 동작하도록 인터페이스 분리.
- [ ] `simulator/tests/`: 계약 검증 통과/실패 케이스, seed 재현성 테스트, 오류 시나리오별 테스트(6개 이상).

### 완료 기준 (원본 로드맵)

정상 프레임 검증 통과 / 잘못된 값 거부 / 동일 seed 재현 / 6개 이상 장애 시나리오 테스트 통과.

## 3단계 — 수집·저장 파이프라인 (Day 5~7)

**선행**: 2단계의 `TelemetryFrame` 계약 확정

### 작업

- [ ] Alembic migration: `assets`, `telemetry_frames`(PostGIS `geometry(PointZ,4326)` 포함),
      `asset_latest_state` 테이블. 인덱스: `(asset_id, event_time desc)`, `unique(asset_id, sequence_no)`,
      GiST 공간 인덱스.
- [ ] `backend/app/modules/ingestion/`: `POST /telemetry` 구현 — 스키마 검증, `asset_id+sequence_no` 중복
      판정, Redis Streams producer로 발행.
- [ ] Redis Streams consumer group 구현 (`realtime` 또는 별도 worker): 원본 저장(SAVE)과 최신 상태 갱신
      (RULE 경로의 축소판)을 분리 처리.
- [ ] 역순 데이터 정책: 원본은 항상 저장하되 `asset_latest_state`는 `event_time`이 후퇴하면 갱신하지 않음.
- [ ] `backend/app/modules/telemetry/`: `GET /assets/{id}/latest`, `GET /assets/{id}/telemetry`(기간·페이지
      네이션) 구현.
- [ ] 기본 메트릭: 수신량·거부량·처리 지연 (Prometheus client, `/metrics` 노출).
- [ ] `backend/tests/`: 손실 없음, 중복 미반영, 역순 미후퇴, 기간 조회 통합 테스트.
- [ ] 시뮬레이터를 실제 `POST /telemetry`에 연결해 end-to-end 확인, `docker-compose --profile
      with-simulator` 동작 검증.

### 완료 기준

10대 무손실 저장 / 중복 이중반영 없음 / 역순이 최신상태 후퇴시키지 않음 / 이력 조회 테스트 통과.

## 4단계 — 2D 실시간 관제 (Day 8~10)

**선행**: 3단계 API·데이터 확정

### 작업

- [ ] `backend/app/modules/realtime/`: `/ws/operations` WebSocket — 연결 시 최신 스냅샷 전송 후 구독,
      재연결 지원.
- [ ] `frontend/src/ws/useTelemetryStream.ts`: 실제 WS 클라이언트, 재연결/backoff, stale 판정.
- [ ] `frontend/src/store/useOperationsStore.ts`: 자산별 최신 프레임 상태 갱신 로직(Zustand).
- [ ] `frontend/src/components/OperationsMap/`: MapLibre 지도, 방향 아이콘·호출부호·상태색, 실제 이동
      경로(실선), 통신 단절 시 회색 마지막 위치+경과시간.
- [ ] `frontend/src/components/AssetList/`: 목록·검색·상태 필터.
- [ ] `frontend/src/components/AssetDetail/`: 선택 기체 상세 패널, 지도 선택과 동기화.
- [ ] TanStack Query로 초기 자산 목록/최신 상태 조회, WS와 병행.
- [ ] 재연결 후 최신 스냅샷으로 복구되는지 시나리오 테스트(수동 또는 Playwright).

### 완료 기준

10대 아이콘 식별 가능 갱신 / 클릭-패널 정보 일치 / 단절 표시 / 재연결 복구.

## 5단계 — 임무·경보 관리 (Day 11~13)

**선행**: 4단계 실시간 파이프라인

### 작업

- [ ] Migration: `missions`, `mission_routes`(LineStringZ), `geofences`(Polygon), `alerts`, `audit_logs`.
- [ ] `backend/app/modules/mission/`: 임무·경유지·예정경로 CRUD, 지오펜스 CRUD.
- [ ] `backend/app/modules/alert/`: 규칙 엔진(배터리 부족, RSSI 저하, 지오펜스 이탈) — 텔레메트리 스트림
      구독, 경보 생성 시 근거값·임계값·`rule_version` 저장, 확인/해제 상태 전이.
- [ ] `backend/app/modules/audit/`: 임무·경보·구역 변경 등 주요 행위를 `audit_logs`에 기록하는 공통 데코레이터/미들웨어.
- [ ] Frontend: 임무 관리 화면(경로 지도 표시, 점선), `AlertPanel`을 실제 `/alerts` API + WS 이벤트에 연결.
- [ ] 규칙 테스트: 3종 경보 각각 시나리오 기반 테스트, 감사 로그 기록 확인 테스트.

### 완료 기준

예정 경로 점선 표시 / 3종 경보 재현 / 경보별 근거·규칙버전 조회 / 변경행위 감사 로그 기록.

**선행**: 5단계까지의 자산·자세 데이터

### 작업

- [ ] 축 정의 문서 작성(예: `docs/planning/06_3D_축정의.md` 또는 기존 문서에 추가): ENU/NED ↔ three.js
      좌표계 매핑.
- [ ] `frontend/src/components/Vehicle3DViewer/`: three.js 씬, GLB 로딩·로딩중/오류 상태, roll/pitch/yaw
      → quaternion 적용, 진행방향/센서방향 보조선.
- [ ] 기체 변경 시 geometry/texture dispose로 메모리 정리.
- [ ] React 오류 경계로 3D 실패가 2D 관제를 중단시키지 않도록 격리(`frontend/src/App.tsx` 또는 상위

      quaternion 계산 검증).

### 완료 기준

선택 기체-뷰어 asset_id 일치 / 회전 테스트 통과 / timestamp 2D와 일치 / 3D 실패해도 2D 정상.

**선행**: 7단계까지 기능 완성, 전체 통합 안정화

### 작업

- [ ] `backend/app/modules/identity/`: JWT 인증, 운영자/분석자/관리자 역할 기반 권한 검사(엔드포인트별
