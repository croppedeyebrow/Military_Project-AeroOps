## 구현 내역

### 백엔드 — 실시간(WebSocket)

- [`app/modules/realtime/broadcaster.py`](../../../legacy-backend/app/modules/realtime/broadcaster.py):
  `asyncio.Queue` 기반 프로세스 내 브로드캐스터. ADR 0001(단일 프로세스 모놀리스)이라
  telemetry consumer와 WS 핸들러가 같은 프로세스에 있으므로 Redis Pub/Sub 없이 충분하다.
- [`app/modules/telemetry/consumer.py`](../../../legacy-backend/app/modules/telemetry/consumer.py):
  `_handle_message`가 `asset_latest_state`가 실제로 갱신됐을 때만(중복·역순이면 안 함)
  완전한 `TelemetryFrame`을 만들어 반환하고, `run_consumer_loop`가 그걸 브로드캐스터에
  발행하도록 수정.
- [`app/modules/realtime/router.py`](../../../legacy-backend/app/modules/realtime/router.py):
  `WS /ws/operations` — 연결 시 `get_all_latest_states`로 전체 스냅샷 1회 전송 후 구독.
  disconnect 감지를 위해 "갱신 전달" task와 "recv 감시" task를 `asyncio.wait(...,
  FIRST_COMPLETED)`로 경합시킨다(서버가 push만 하고 클라이언트는 아무것도 안 보내는
  단방향 스트림이라, 연결 종료를 감지하려면 별도로 recv를 계속 걸어둬야 한다).
- [`app/modules/telemetry/repository.py`](../../../legacy-backend/app/modules/telemetry/repository.py):
  `get_all_latest_states`(스냅샷용), `get_max_sequence_no`(재동기화 gap 계산용) 추가.
- [`app/modules/telemetry/router.py`](../../../legacy-backend/app/modules/telemetry/router.py):
  `GET /assets`(전체 최신 상태 목록) 신설 — 프론트 초기 페인트(TanStack Query)용.

### 백엔드 — 재동기화(Sync)

- [`app/modules/sync/models.py`](../../../legacy-backend/app/modules/sync/models.py): `SyncSession`
  (append-only), migration `0003_sync_sessions_table.py`.
- [`app/modules/sync/repository.py`](../../../legacy-backend/app/modules/sync/repository.py):
  `perform_sync` — 서버 저장분(`get_max_sequence_no`)과 기체가 보고한
  `last_sequence_no`를 비교해 (a) 기체가 앞서면 손실 구간(sequence gap) (b) 기체가
  뒤처지면 `device_behind_server` 이상 징후로 구분. `commands` 중 터미널 상태가 아닌
  것을 미종결 명령으로 조회. 판단 결과를 매번 `sync_sessions`에 기록.
- [`app/modules/sync/router.py`](../../../legacy-backend/app/modules/sync/router.py):
  `POST /devices/{asset_id}/sync`.

## 설계 결정

- **Redis Pub/Sub 대신 in-process 브로드캐스터**: consumer와 WS 핸들러가 같은 프로세스
  (ADR 0001)라 `asyncio.Queue`로 충분하다. 여러 API 인스턴스로 늘리면(8단계 이후 클라우드
  확장 시) Redis Pub/Sub로 옮겨야 하고, 그때는 Telemetry/Command처럼 이것도 별도 채널·
  ACL을 고민해야 한다 — 지금은 그 복잡도를 지불하지 않는다.
- **"resume" 프로토콜 없이 매 연결마다 전체 스냅샷**: 클라이언트가 마지막으로 어디까지
  받았는지 서버가 추적할 필요가 없어진다. 10대 규모 MVP에서 스냅샷 재전송 비용은
  무시할 만하다.
- **ResyncBanner ≠ sync 모듈**: `sync`는 기체↔서버 재동기화(백엔드 API만 존재, 브라우저가
  기체 역할을 하지 않으므로 UI 없음)이고, `ResyncBanner`는 브라우저↔서버 WebSocket
  재연결을 보여주는 순수 UI 신호다. 이름이 비슷해 헷갈리기 쉬워 컴포넌트 README에
  명시적으로 구분해뒀다.
- **`TelemetryFrame` 타입을 snake_case로 통일**: 기존 스텁은 camelCase였다. 서버가 실제로
  보내는 JSON과 다른 이름 체계를 쓰면 그 변환 계층 자체가 버그 표면이 된다 — 계약 문서와
  1:1 대응시키는 쪽이 더 안전하다고 판단했다.
- **마커를 스프라이트 이미지 대신 CSS 삼각형으로**: 아이콘 애셋 파이프라인(이미지 준비,
  라이선스, sprite 빌드) 없이 방향·색상을 표현할 수 있다. 10대 규모라 `maplibregl.Marker`
  (HTML 기반)의 성능 오버헤드도 무시할 만하다. 저폴리곤 3D 모델은 6단계에서 별도로
  다룬다.
- **재동기화의 "미종결 명령" 판정이 아직 근사치**: 명령 상태 머신(5단계)이 없어 모든
  명령이 `DRAFT`다. `TERMINAL_COMMAND_STATUSES` 집합을 미리 정의해뒀으니, 5단계에서
  실제로 상태가 전이되기 시작하면 `sync` 모듈 코드 변경 없이 의미가 저절로 좁혀진다.

## 테스트/검증

```
cd backend && ruff check .    # 통과
cd backend && pytest          # 서비스 없음: 30 passed, 16 skipped
                               # 서비스 있음(docker postgres+redis): 55 passed
cd simulator && pytest && ruff check .   # 50 passed, 변경 없음(회귀 확인)
cd frontend && npm run lint   # 0 errors, 2 warnings(ref cleanup, 의도된 패턴)
cd frontend && npm run build  # 통과
cd frontend && npm run test   # 25 passed (vitest + jsdom)
```

실제 Postgres/Redis(임시 docker, 검증 후 삭제) + 실제 backend 서버 + 실제 프론트 dev
서버 + 실제 시뮬레이터로 확인:

- `POST /telemetry` → `/ws/operations` 스냅샷/업데이트, `GET /assets`, `POST
  /devices/{id}/sync`(gap·anomaly·미종결 명령 3개 시나리오 + 신규 기체) 전부 수동 확인.
- Node의 내장 `WebSocket` 클라이언트로 `/ws/operations`에 직접 접속해 스냅샷 메시지의
  필드가 프론트 `TelemetryFrame` 타입과 정확히 일치함을 확인(19개 필드 전부 매치).
- 프론트 dev 서버가 정상적으로 페이지를 서빙하는지 확인(`curl`로 HTML 확인).

## 남은 이슈 / 다음 단계로 이월

- **실제 브라우저에서의 시각적 확인은 하지 못했다** — 이 세션에 브라우저 자동화 도구가
  없어 지도가 실제로 어떻게 그려지는지 스크린샷 등으로 확인할 수 없었다. 데이터가 정확히
  브라우저 JS가 기대하는 형태로 도달함(WS 메시지 shape 일치)과 로직 단위(스토어·백오프·
  마커 DOM 조작)는 vitest로 검증했지만, "실제로 지도에 10대가 잘 보이는지"는 사용자가
  `npm run dev`로 직접 열어 확인해야 한다.
- 예정 경로(점선)·지오펜스 폴리곤 레이어는 5단계에서 `OperationsMap`에 추가한다.
- "재동기화 완료 전 위험 명령 제한"은 명령 dispatch 자체가 없어 검증 대상이 없다 —
  5단계에서 실제로 구현·검증한다(작업분해 문서에 기록).
- `ResyncBanner`가 보여주는 재연결은 WS 연결 기준이지, 기체의 실제 `sync_sessions` 결과를
  보여주는 화면은 아직 없다 — 필요해지면 이후 단계에서 조회 화면을 추가한다.
- 프론트 프로덕션 번들이 500KB 경고를 넘는다(maplibre-gl이 큼) — 기능에는 영향 없고,
  필요해지면 code splitting으로 개선할 수 있다.
