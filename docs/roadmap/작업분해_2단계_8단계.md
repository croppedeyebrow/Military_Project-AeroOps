# 2~8단계 작업 분해 (v3 — OPS 운용 문제·AI/MLOps·DevSecOps 반영)

## 개정 배경

2026-09-13 기준 `docs/planning/*`, `docs/roadmap/*`이 대폭 확장됐다. 기존 MVP(텔레메트리
수집·2D 관제·임무·경보)에 다음이 추가됐다:

- **Command/Telemetry 채널 분리**: 기체 제어 명령(`CommandEnvelope`)을 텔레메트리와 다른
  계약·스트림·계정·API로 분리하고, 요청→승인→전달→ACK→실행→완료/취소/타임아웃 상태 머신으로
  관리한다.
- **기체 mTLS**: 기체별 client certificate로 신원을 증명하고, 만료·미등록·폐기·타 기체
  인증서를 거부한다.
- **재동기화(Sync)**: 통신 단절 후 재연결 시 sequence·state_version·미종결 명령을 대조해
  snapshot을 다시 맞춘다.
- **이벤트 재생·배포 추적**: 모든 이벤트에 `operation_session_id`/`deployment_id`를 연결해
  append-only event log로 재생하고, 장애 시점의 Git SHA/이미지 digest/규칙 버전을 역추적한다.

이 문서는 이전 버전(단순 MVP 기준)을 **대체**한다. 1~3단계는 이미 구현·커밋된 상태이므로,
"완전 재작성" 대신 **① 기존 구현 중 유지되는 부분 ② 새 계약/스키마에 맞춰 보정해야 하는 부분
③ 새로 추가해야 하는 부분**을 구분해서 정리한다.

**문제**: 이 V03/V04 절이 이미 "완료" 처리된 1~5단계 로드맵 문서에도 소급 적용되어 있다

**결정(사용자 확인, 2026-10-10)**: 1~5단계의 V03/V04 보정은 지금 당장 처리하지 않는다.
**6단계부터 로드맵 순서대로 먼저 진행**하고, AI/보안 레이어가 실제로 필요해지는 시점

이유: 통제권 Lease·임무 가능성·ML 피처 파이프라인 등은 독립적으로 무게감 있는 서브시스템이라,
지금 끼워 넣으면 핵심 기능(3D 뷰어 등) 진행이 지연된다. 아래 "1~5단계 V03/V04 보정 백로그"에

## 진행 원칙

- 각 단계(또는 보정 작업) 착수 전 사용자 승인을 받은 뒤 구현한다.
- 단계 완료 시 README의 "현재 상태" 배지와 `docs/decisions/`에 필요한 ADR을 갱신한다.
- 매 단계 종료 시 `docker compose up`으로 전체 서비스가 여전히 기동되는지 확인한다.
- 백엔드 모듈 경계 — 기존: `ingestion, telemetry, mission, alert, realtime, identity, audit` +
  신설: `command, device_identity, sync, deployment` — 와 프론트 컴포넌트 경계(기존 7개 +
  `CommandComposer, ApprovalQueue, CommandTimeline, LinkQualityPanel, ResyncBanner,
  DeploymentBadge`)를 유지한다.
- Telemetry는 "유실 허용, 고빈도, 기체→서버 단방향"이고 Command는 "저빈도, 서버→기체,
  인증·승인·ACK·감사 필수"라는 성격 차이를 코드 경계(스키마·스트림·계정·API)로 항상 분리한다.
