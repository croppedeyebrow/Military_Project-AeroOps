# 현행 레포 분석과 전환 범위

## 1. 분석 기준

- 대상: `croppedeyebrow/Military_Project-AeroOps`
- 기준 브랜치: `master`
- 확인일: 2026-10-19
- 원칙: 레포는 변경하지 않고 공개된 구조와 설정을 기획 기준선으로 사용한다.

## 2. 현재 구현 상태

현재 레포는 문서만 있는 초기 프로젝트가 아니다. FastAPI 기반으로 7단계까지 진행되어 명령 상태 머신, Telemetry 수집, Redis ACL 채널 분리, 재동기화, 이력 재생과 관측성이 구현되어 있다. 따라서 전환 목표는 기능 재작성 자체가 아니라 기존 불변조건을 보존하면서 책임을 새 언어와 경계 컨텍스트로 옮기는 것이다.

| 현행 영역 | 확인된 구현 | 판정 |
|---|---|---|
| Frontend | React 18, TypeScript, Vite, MapLibre, Three.js, Zustand, React Query | 유지·계약만 변경 |
| Backend | FastAPI, Pydantic, SQLAlchemy/Alembic, WebSocket | Kotlin/Spring Boot로 단계 이관 |
| Simulator | Python 가상 기체·장애 주입 | C++로 재작성, Python은 비교 기준으로 한시 보존 |
| Messaging | Redis Streams, Command/Telemetry ACL 분리 | 계약 유지, Rust Gateway 앞단 추가 |
| Database | PostgreSQL/PostGIS, Alembic 5개 Migration | 데이터 보존, Flyway Baseline 도입 |
| Observability | Prometheus custom metric, Grafana dashboard | 유지, Go exporter/ops 도구 보강 |
| Deployment | Docker Compose, GitHub Actions | 다언어 Matrix와 Go 배포 검증으로 확장 |
| Reliability | ACK·timeout·재동기화·event replay | 회귀시험의 최우선 보존 대상 |

## 3. 현행 기능과 목표 경계 컨텍스트 매핑

| 현행 Python 모듈 | 목표 경계 컨텍스트 | Kotlin 이관 대상 | 별도 언어 경계 |
|---|---|---|---|
| `mission` | Mission Operations | Mission Aggregate·경로·상태 전이 | 없음 |
| `command` | Command & Control | 승인·취소·timeout·효과 검증 | Rust가 전송만 담당 |
| `telemetry` | Operational Picture | 최신 상황도·Freshness Projection | Rust 수신, C++ 생산 |
| `ingestion` | Communications Resilience ACL | 정규화 이후 Use Case | Rust Gateway가 framing·검증 |
| `sync` | Communications Resilience | 조정 정책·결과 기록 | Rust가 snapshot/sequence 교환 |
| `alert` | Incident Management | 규칙·사건·확인/해제 | Python ML이 이상 후보 제공 |
| `audit` | Identity & Audit | 불변 감사·행위자·정책 버전 | Go가 배포 증거 연결 |
| `deployment` | Deployment Registry | 운용 세션·Artifact 메타데이터 | Go가 검증·배포 실행 |
| `device_identity` | Device Trust | 인증서 상태·장비 매핑 | Rust가 mTLS 연결 적용 |
| `realtime` | Operational Picture Query | WebSocket Snapshot/Event | React가 소비 |

## 4. 보존해야 할 불변조건

1. 오래된 Telemetry가 최신 상태를 후퇴시키지 않는다.
2. 동일 `command_id`는 기체에서 두 번 실행되지 않는다.
3. ACK 누락을 실행 실패로 단정하지 않는다.
4. 승인과 Dispatch 사이에 권한·통제권·만료를 다시 검사한다.
5. 단절 후 snapshot, sequence, 미종결 명령을 대조한다.
6. Command와 Telemetry는 계정·ACL·Stream·우선순위가 분리된다.
7. 운용 세션에서 Git SHA, image digest, schema·policy version을 역추적할 수 있다.
8. 동일 시나리오 seed로 전환 전후 결과를 Replay 비교할 수 있다.

## 5. 이번 전환에서 하지 않는 것

- React 화면의 전면 재설계
- PostgreSQL 데이터의 일괄 폐기
- Redis Streams를 Kafka로 교체
- 즉시 Kubernetes 도입
- 실제 무기·표적화·공격 자동화
- LLM에 Command 발행 권한 부여
- 검증 전 FastAPI 코드 삭제

## 6. 전환 성공 기준

- Kotlin이 Mission·Command·Operational Picture의 System of Record가 된다.
- 동일 Contract/E2E 시험을 FastAPI와 Kotlin에 실행했을 때 핵심 결과가 일치한다.
- C++ Simulator→Rust Gateway→Kotlin Core→React UI의 전체 경로가 동작한다.
- Python AI 장애가 C2 운용과 명령 처리에 영향을 주지 않는다.
- Go 도구가 승인 Artifact 검증, 배포, Health Gate, Rollback 증거를 만든다.
- 이전 API 제거 전 최소 2회의 완전 Replay와 장애 회귀시험을 통과한다.
