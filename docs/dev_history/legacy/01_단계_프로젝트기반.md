### 구현 내역

- 백엔드 모듈 스캐폴드 4개 신설(README만, 코드는 각 담당 단계에서 채움):
  `command`(3단계 최소 골격 → 5단계 완성), `device_identity`(8단계), `sync`(4단계),
  `deployment`(1단계 보정에서 build-info로 시작 → 7단계 완성).
- 환경변수 네임스페이스 분리: `.env.example`에 `TELEMETRY_STREAM_NAME`/
  `TELEMETRY_CONSUMER_GROUP`과 `COMMAND_STREAM_NAME`/`COMMAND_CONSUMER_GROUP`을 추가하고
  `app/core/config.py`의 `Settings`에 필드로 반영(기본값은 기존 하드코딩 값과 동일해
  동작 변화 없음 — 실제 배선은 "3단계 보정"에서).
- `GET /system/build-info`(`app/modules/deployment/router.py`): `GIT_SHA`, `IMAGE_TAG`,
  `schema_version`(alembic migration 스크립트 기준 head revision, DB 연결 없이 계산)을
  반환.
- `backend/Dockerfile`: `ARG GIT_SHA`/`ARG IMAGE_TAG` → `ENV`로 전달. `docker build
  --build-arg GIT_SHA=$(git rev-parse HEAD) --build-arg IMAGE_TAG=...`로 주입.
- `infra/docker-compose.yml`: `api` 서비스 `build.args`에 `GIT_SHA`/`IMAGE_TAG`(compose
  실행 환경변수에서 전달, 기본값 `local-dev`).

### 설계 결정

- `schema_version`은 DB에 실제 적용된 버전이 아니라 **코드가 기대하는(포함하고 있는)**
  migration head를 반환한다 — DB가 잠깐 내려가 있어도 build-info는 계속 응답해야 하고,
  "DB 현재 상태"는 이미 `/health/ready`가 별도로 책임지기 때문이다.
- Redis 스트림 네임스페이스는 지금 단계에서 자리만 만들고 실제 배선(코드에서 `settings.
  telemetry_stream_name` 등을 사용하도록 바꾸는 것)은 하지 않았다 — 채널 분리는 "3단계
  보정"의 책임이라 여기서 앞서가지 않는다.

