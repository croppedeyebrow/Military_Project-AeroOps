# 데이터엔지니어링 아키텍처

## 데이터 계약

`TelemetryFrame`은 `schema_version`, `asset_id`, `mission_id`, `operation_session_id`, `deployment_id`, `event_time`, `received_at`, `boot_id`, `sequence_no`(부팅 내 단조 증가, [ADR 0005](../decisions/0005-telemetry-boot-id.md)), 위치, 속도, heading, roll·pitch·yaw, 배터리, RSSI, 비행 모드를 포함한다.

위치·자세·배터리·통신처럼 갱신 주기가 다른 상태는 필드 그룹별 `observed_at`, 품질 코드와 신선도 TTL을 정의한다. 하나의 Frame 수신을 모든 값의 최신성으로 간주하지 않는다.

`CommandEnvelope`은 `command_id`, `idempotency_key`, `target_asset_id`, `command_type`, `payload`, `requested_by`, `approved_by`, `issued_at`, `expires_at`, `expected_asset_state_version`, `deployment_id`를 포함한다. Telemetry와 Command 스키마·토픽·보존 정책은 분리한다.

## 파이프라인

```mermaid
flowchart LR
    GEN["Telemetry 생성"] --> CHECK["계약·sequence 검증"]
    CHECK --> TSTREAM["Telemetry Stream"]
    CMD["승인된 Command"] --> CSTREAM["Command Stream"]
    TSTREAM --> STATE["최신 상태"]
    TSTREAM --> RAW["원본 이력"]
    CSTREAM --> RAW
    RAW --> FEATURE["구간·특징 집계"]
    FEATURE --> REPORT["경보·품질 리포트"]
```

## 품질 규칙

| 차원 | 검사 |
|---|---|
| 완전성 | 필수 필드와 결측률 |
| 유효성 | 좌표·각도·배터리·RSSI 범위 |
| 유일성 | asset·sequence 중복 |
| 적시성 | event와 received 시각 차이 |
| 순서성 | 기체별 sequence·timestamp 역전 |
| 일관성 | heading과 yaw 정의, 단위·좌표계 |
| 연속성 | sequence gap과 단절 구간 |
| 추적성 | operation·deployment·correlation 연결 |
| 신선도 | 필드 그룹별 observed_at·TTL·quality code |
| 판단가능성 | 필수 입력 부족 시 UNKNOWN 처리 |

## 장애 시나리오

시뮬레이터에서 패킷 손실, 중복, 지연, 역순, 결측, 급격한 배터리 하락, GPS 점프, 통신 단절과 ACK 손실을 주입한다. 각 시나리오의 기대 처리 결과를 테스트 픽스처로 고정한다.

## 분석 데이터

MVP 특징은 배터리 소모율, 속도·고도 변화율, 수신 지연, RSSI 이동평균, 지오펜스 거리로 제한한다. 초기 경보는 설명 가능한 규칙 기반으로 구현하고 ML은 후속 비교 실험으로 둔다.

## 재현성

- schema·rule·simulator 버전을 기록한다.
- 원본을 덮어쓰지 않고 분석 결과에 버전을 연결한다.
- 고정 seed 시나리오로 데모와 회귀시험을 재현한다.

## 이벤트 재생

- 수신 원본과 정규화 이벤트를 append-only로 보존한다.
- 재생기는 `operation_session_id`와 시간 범위를 입력받아 원래 event-time 순서를 복원한다.
- 실제 도착 순서와 이벤트 발생 순서를 모두 보존하여 지연·역순 현상을 재현한다.
- 재생 출력은 운영 스트림과 분리된 replay namespace로 보내 실제 명령 실행을 차단한다.
- 재생 결과에 원본 deployment_id와 현재 replay engine 버전을 함께 기록한다.

## 재동기화 데이터 규칙

기체가 마지막 송신 sequence, 현재 state_version, 처리한 마지막 command_id를 제출한다. 서버는 저장 상태와 비교해 누락 telemetry 표시, 미종결 명령 조정, snapshot 교체 여부를 결정하고 모든 판단을 sync event로 남긴다.

## AI 데이터 파이프라인

```text
raw events
→ schema/quality validation
→ canonical events
→ time-window features
→ labeled scenario dataset
→ train/evaluate
→ registry/deploy
→ prediction/feedback
```

- 시뮬레이터의 Fault Rule을 초기 Label로 사용하되 서버 관측 결과와 분리한다.
- 데이터 분할은 동일 `simulation_run_id`가 Train과 Test에 동시에 들어가지 않도록 한다.
- Dataset Snapshot에는 Query, Schema, Scenario, Seed, Hash를 기록한다.
- Feature 계산에는 Event Time을 사용하고 수신 지연 Feature에는 Received Time을 사용한다.
- LLM/RAG 평가 데이터는 질문, 기대 문서, 기대 Event, 금지 행동을 포함한다.

## 데이터 품질 게이트

- 필수 필드 누락률, Sequence 중복률, 시간 역전률
- 좌표·각도·배터리 범위 위반
- Feature Null·Inf·분포 변화
- Knowledge 문서 중복·빈 Chunk·ACL 누락
- 학습-서빙 Feature Schema 불일치

품질 실패 데이터는 격리하며 자동으로 Production 모델 학습에 포함하지 않는다.
