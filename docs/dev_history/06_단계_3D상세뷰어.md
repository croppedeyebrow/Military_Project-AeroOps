### 좌표축 규칙

- [`docs/decisions/0003-vehicle-3d-axis-convention.md`](../decisions/0003-vehicle-3d-axis-convention.md):
  장면 좌표계(+X=동, +Y=상, +Z=남), `THREE.Euler("YXZ")` 순서, 각 성분 부호
  (`yaw: -heading`, `pitch: +pitch`, `roll: -roll`)를 수식과 근거로 고정. 시뮬레이터
  실제 생성 규칙(`yaw_deg = to_signed_deg(heading_deg)`, `pitch_deg`는 현재 항상 0)을
  먼저 확인한 뒤 작성했다.

### Vehicle3DViewer 컴포넌트

- [`frontend/src/components/Vehicle3DViewer/attitude.ts`](../../frontend/src/components/Vehicle3DViewer/attitude.ts):
  자세→쿼터니언 변환과 전방/우측/상방/진행방향 벡터를 순수 함수로 분리(WebGL 없이
  vitest 검증 가능하게).

  박스(동체)+실린더 4개(암)+원판 4개(프로펠러)로 구성한 저폴리곤 placeholder. 외부
  GLB 파일·라이선스 표기가 전혀 필요 없다.
- [`guides.ts`](../../frontend/src/components/Vehicle3DViewer/guides.ts): 진행방향
  (heading만, 항상 수평)과 기수/센서 방향(전체 자세) `ArrowHelper` 2종.
- [`Vehicle3DErrorBoundary.tsx`](../../frontend/src/components/Vehicle3DViewer/Vehicle3DErrorBoundary.tsx):
  3D 렌더 예외를 잡아 2D 관제·명령 콘솔은 계속 동작하게 격리.
- [`Vehicle3DViewer.tsx`](../../frontend/src/components/Vehicle3DViewer/Vehicle3DViewer.tsx):
  렌더러/씬/카메라는 마운트 시 1회 생성(언마운트 시 전체 dispose), 기체 선택이 바뀔
  때만 drone 메시+보조선을 dispose 후 재생성, 텔레메트리 갱신 시 쿼터니언만 갱신하고
  1프레임 렌더(상시 애니메이션 루프 없음 — 텔레메트리가 ~1Hz라 불필요). `classifyFreshness`
  로 STALE/통신 단절 시 "오래된 자세값일 수 있음"을 텍스트로 표시하고, `useAssetCommandsQuery`
  (`api/commands.ts` 신설)로 선택 기체의 최근 명령을 조회해 "최근 연관 명령" 배지로
  표시한다.
- `App.tsx`: "기체 상세" 탭 안에 `Vehicle3DViewer`를 `AssetDetail` 위에 배치.

## 설계 결정

- **GLB 대신 Three.js 프리미티브로 drone 모델 생성**: 사용자가 "일단 Three.js로 하고
  추후에 헬기/드론 관련 GLB파일을 넣는거로" 결정(2026-10-10). 로드맵의 "라이선스 명확한
  저폴리곤 GLB 선정"은 **아직 하지 않았다** — 아래 "남은 이슈" 참고. 대신 모델 자체를
  `buildDroneMesh.ts` 함수로 캡슐화해, 추후 `GLTFLoader` 결과로 교체할 때 자세 변환
  로직(`attitude.ts`)과 나머지 컴포넌트는 그대로 둘 수 있게 했다.
- **렌더 루프 없이 이벤트 기반 렌더**: 텔레메트리가 ~1Hz로 갱신되는데 60fps
  `requestAnimationFrame` 루프를 돌리는 건 낭비다. 자세가 바뀔 때(React effect
  dependency)만 쿼터니언을 갱신하고 `renderer.render()`를 한 번 호출한다.
- **"로딩중" 상태는 구현하지 않음**: 현재 지오메트리는 동기 생성이라 실제 비동기
  로딩이 없다. GLB 교체 시 `GLTFLoader`의 콜백으로 추가한다(README에 명시).
- **명령-자세 연결은 최소 배지로 구현**: `CommandStatus`(`command_id`/`status`/
  `updated_at`)만으로 "최근 연관 명령" 한 줄을 보여준다. 자세 변화 시점과 명령 이벤트
  시각을 그래프로 겹쳐 보여주는 것은 7단계 재생(`ReplayTimeline`/`TelemetryChart`)의
  몫으로 남긴다 — 지금 시점에 그래프를 만들면 재생 축 설계와 중복 작업이 된다.

## 테스트/검증

```
cd frontend && npm run lint   # 0 errors, 기존 2개 warning만(OperationsMap 리팩터 전부터 있던 것)
cd frontend && npm run build  # 통과
cd frontend && npm run test   # 38 passed (attitude.test.ts 10건 신규)
```

`attitude.test.ts`로 확인한 것(ADR 0003의 "검증 기준" 그대로):

- 기준 자세(0,0,0): 전방벡터 `(0,0,-1)`(북), 상방벡터 `(0,1,0)`.
- heading 90/180/270에서 전방벡터가 각각 동/남/서를 향함.
- pitch ±30에서 전방벡터 Y 성분 부호가 기수 상승/하강과 일치.
- roll ±30에서 우측벡터 Y 성분 부호가 우익/좌익 하강과 일치.
- `headingGroundVector`는 항상 수평(Y=0)이고, 자세가 0일 때 `forwardVector`와 일치.

## 남은 이슈 / 다음 단계로 이월

- **GLB 모델 선정이 아직 안 됐다**: 로드맵 완료 기준 중 하나를 의도적으로 미루고
  진행했다(위 "설계 결정" 참고). 실제 3D 뷰어는 지금 저폴리곤 placeholder 기하로
  동작한다 — 겉보기는 드론이 아니라 단순 쿼드콥터 형상의 상자+막대+원판이다.
- GLB 로딩/로딩중/오류 상태의 "로딩" 부분은 placeholder가 동기 생성이라 구현하지
  않았다. GLB 교체 시 추가해야 한다.
- 카메라 조작(OrbitControls)과 리사이즈 대응은 하지 않았다(고정 폭 우측 패널 안이라
  실익이 적다고 판단) — MVP 범위 밖으로 명시.
- 자세 변화-명령 연결은 최소 배지(가장 최근 명령 1건)뿐이다. 특정 자세 변화가 "어느
  명령 때문인지" 시간축으로 정밀하게 겹쳐 보여주는 것은 7단계 재생 화면의 몫이다.
- 6단계 로드맵 V03 추가 태스크(지식베이스 정규화, Hybrid Retrieval/RRF)는 이번
  작업에 포함하지 않았다 — 사용자 결정(2026-10-10)에 따라 AI/보안 레이어는 6~8단계
  진행 중 별도로 다룬다(`docs/roadmap/작업분해_2단계_8단계.md`의 "1~5단계 V03/V04 보정
  백로그" 참고 — 6단계 자체도 V03은 이번에 하지 않고 핵심 라인만 마쳤다).
- 여전히 브라우저 화면을 직접 본 적은 없다 — 이번 세션에는 브라우저 제어 도구가
  연결되어 있지 않아 lint/build/vitest(순수 함수 자세 수학)로만 검증했다. 실제 렌더링
  확인은 사용자가 `npm run dev`로 열어봐야 한다.
