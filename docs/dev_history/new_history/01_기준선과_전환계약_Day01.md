## 설계 결정 (Day 1 이후 확정, 2026-10-24)

- **스키마 소유는 Kotlin(Flyway)**: 제안(Alembic 유지)을 바꿔 승인. Alembic은 `0005`에서 동결하고
  Flyway Baseline이 이를 이어받는다. legacy가 쓰는 테이블은 Expand 전용으로만 변경한다.
- **`boot_id` 제약 교체 시점**: legacy의 `ON CONFLICT (asset_id, sequence_no)` 때문에 Telemetry 쓰기
  주체가 Kotlin으로 넘어가는 시점으로 늦춘다.
- **레포 구조**: FastAPI를 `legacy-backend/`로 이동(삭제 아님), `backend/`는 Kotlin 전용.

## Day 1 이후 보정 (2026-10-24) — 학습 로드맵 검증에서 나온 현행 결함 3건 수정

- **D-1** 멱등 충돌이 `command_type`·대상·요청자를 안 봐서 200으로 기존 명령 반환 → 409. 기존 시험은 `command_id`가 호출마다 달라 통과하던 것이라 실제 의도를 검증하지 못했다(시험 재작성).
- **D-3** 다른 키로 쓰인 `command_id` 재사용 시 500 → 409.
- **D-2** consumer가 실패해도 항상 XACK해 접수된 프레임이 유실 → 일시 실패 재전달(`XAUTOCLAIM`), 영구 실패·재시도 소진은 dead-letter. **실제 장애 검증**: 120프레임 전송 중 Postgres 5초 중단 시 이전 코드는 접수 120/저장 109(11건 유실), 수정 코드는 120/120.
- 시험은 먼저 이전 코드에서 실패(red)하는 것을 확인한 뒤 수정 코드에서 통과(green)시켰다. 전체 `pytest` 148 passed(깨끗한 격리 환경).
- Golden에 `conflict_type`·`conflict_id` 흐름 추가(명령 9종). 기존 결과는 변하지 않았다(52줄 추가·삭제 0).
- 상세·알려진 한계: `docs/planning/13` §6.
